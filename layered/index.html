Words on this pageSeven words, in plain English

Ratio (×)
Original size divided by squeezed size. 4× means a quarter of the bytes. Every ratio here counts every header byte, and is pooled: all items' bytes over all their frames' bytes.
Layer, dimension, fold
A family of guesses about the next byte. D1 guesses from how often each byte occurs; D2 from the word being written; D3 from the field or line it sits in; D4 from the last few bytes and long repeats; D5 from what both ends already hold. The fold depth is how many layers a frame used.
Seed
What both ends already share, taught to the codec before the first byte. It can grow: every item two ends exchange can be added to it.
Cold frame and whisper
A cold frame (D1 to D4) needs nothing shared and decodes anywhere. A whisper (all five) needs the same seed at both ends; a frame names its seed, and a reader with a different one refuses it.
Lossless
What comes out is exactly what went in, byte for byte, checked by SHA-256.
Sealed, held out
The claims were committed before the code; the instrument was frozen by hash before any held item was read. Held items are dated after the cut, never seen by any tuning.
Pattern, node, settle
A pattern is a verified rule (WHEN word THEN family). Settling it against a case gives its decision or "unknown". A node is a stack of patterns; the first that fires answers.

Traced from the real run

  1. A frame's header says which layers it used (a mask), its table size, the seed's id if it used one, the length, and a 4-byte check of the original.
  2. Prediction is compression. For each bit, the probability the layers give it decides how many bits it costs. A 99% guess costs 0.015 bits; a wrong one costs many.
  3. The seed is the same model taught the shared material first. A frame names it; the reader must hold the same one or it refuses.
  4. Drift: if the reader's seed differs, the sender drops to the cold layers. Always correct; just less squeezed.

Honest scopeWhat this is, and what it is not

  • Bytes, not model tokens. These frames are for storing and sending between machines. A language model cannot read them, so this does not shrink a model bill; the 15× curve (the curve) is the token measurement.
  • Speed. Pure JavaScript, about 100 KB a second each way on one laptop core: fine for messages, records and memory; slow for bulk archives next to zstd.
  • Shared seeds must be kept in step. The codec refuses a mismatched seed rather than guess, and falls back to the cold layers.
  • The star, not a claim. Compression "approaching infinity as minds share everything" is the direction, not a result: new information always costs bits; a seed can only remove what both ends already hold.

Risks, answered straight

  • Is my data safe? It never leaves your systems; the codec is a library, not a service. Every frame carries a check of the original.
  • What if a seed is lost? Keep seeds versioned like any key material; without the seed a whisper cannot be read, by design. Cold frames need no seed.
  • Is it faster than zstd? No. It is smaller, not faster. Use it where bytes cost more than CPU.
  • Who supports it? Supplied by AI Native Solutions; support and terms are agreed per deployment, in each deployment's agreement. The code keeps running without us.

AdoptionRolling it out

  1. Measure first. Run the same ladder on a sample of your own records; keep it if it beats what you use now.
  2. Start cold. Cold frames (D1 to D4) need nothing shared: drop them in where you gzip today.
  3. Grow a seed. For two systems that exchange the same kinds of records, version a seed from the records both already hold; frames name it.
  4. Let it grow. Both ends add what they exchange; ids stay equal; a mismatch falls back, never corrupts.
  5. Stack rules. Decisions you make repeatedly can live as verified rules in the same format, answering before any model is asked.

White paperFive folds and a stack, measured once

1 · The question

LIGHT v1 measured … on its own held JSON (median, its record). The spec argued that number is a flat ceiling and that five dimensions of compression, stacked, multiply towards 15× and beyond. Two theses follow: the folds multiply, and the ratio grows as two ends share more.

2 · Method

Claims sealed before code. Five data types (agent messages, memory, the call book, public JSON records, public prose); everything dated before 5 November 12:00 UTC is the seed side, everything after is held, read first by the measurement. Each held item coded on its own at each fold depth, every header byte counted, every frame decoded and SHA-checked, against gzip, Brotli, zstd (alone and given the same seed) and LIGHT v1. A one-to-one correspondence between layers and families of guesses in a single context-mixing coder. One level up: the estate's pattern library, its gate unchanged, measured on a slice nothing had seen.

    FAQQuestions

    Did it reach 15×?
    …
    Was the 75× in the spec real?
    It was an assumed product of guessed per-layer gains, not a measurement. The measured answer, per type and depth, is the ladder, and the multiply test is here.
    Can I re-run it?
    The public types, completely: CI re-derives every public number from the committed packs on GitHub's machines. The private types (the estate's own messages, memory and call book) only where they live; the record names their snapshot by hash.
    Does the node call a model?
    Not when it answers. The model (the local qwen2.5:7b) only proposed rules, offline; the library's gate decided which to keep. The node's code imports the codec and nothing else, and a test counts zero calls out of it.
