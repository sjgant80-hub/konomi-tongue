What it isA ruler held against the 15× line, every week

The estate has several ways to make what its agents send each other smaller. Each was measured once, on 1 October, and none came near 15× on new messages. A single point can't show whether things are getting better as the estate's shared knowledge grows. So this measures the same codings again on each new week of real messages, with each coder allowed to learn only from what came before that week. If the curve climbs towards 15×, it will show here. If it stays flat, that shows too.

  • A · the tongue's dictionary. Common runs of text are replaced by short glyphs, from a dictionary grown on earlier messages.
  • B · held reference. Any line the reader already holds, word for word, is sent as a short reference instead. This is the "material both sides already have" route: the same idea behind the only high ratio the estate has seen (a program called by its template name). On new messages it can only save the lines that repeat word for word, and the curve shows how few do.
  • C · LIGHT's codec. A compressor primed with a dictionary of the estate's own files. Its output is bytes, not tokens: it makes storage and transport smaller, but a model cannot read it.

Words on this pageWhat each term means here

15×, a ratio
How many times smaller a coding makes the messages. 15× means the same messages carried in one fifteenth of the tokens; 1× means no saving at all. The figure 15 is Simon's line to measure against.
Token, tokenizer
A token is the unit a language model reads and bills: a word, part of a word, or a symbol. The tokenizer is what cuts text into tokens. Here it is qwen2.5's, the model that runs on the estate's own laptop.
A week, a new message
Each point covers seven days, starting from 1 October at 12:00 UTC. A message is new for that week if it was sent during it. The codings learned only from messages sent before the week began.
Lossless
Every coded message is decoded again and compared byte for byte with the original. A coding that changed even one character would fail claim K1.
Standing
When a week closes, the same command measures it and adds it as a new point. Points already recorded are never rewritten.
Seal
The claims (seal 1), then the frozen instrument (seal 2), were committed to the public record before any week was measured, so nothing could be tuned to the result.
Mutation gate
A tool (witness) that breaks the code in small ways, one at a time, and checks that the tests catch every break. Clean means every one was caught.

How it worksOne week at a time, learning only from the past

  1. Snapshot. The agents' messages, each with its timestamp, are copied into a private snapshot pinned by its SHA-256.
  2. Split by time. For each complete week from the sealed cut (1 October, 12:00 UTC), training is everything before the week and the held messages are the week itself. The code checks the split on every point.
  3. Code and count. Each held message is coded three ways, decoded again (it must come back byte for byte), and counted: tokens by the local tokenizer, bytes for LIGHT and gzip.
  4. Publish only numbers. The public file holds counts, ratios, dates and hashes. Every string in it must come from a fixed list the code writes, so no message text can reach it.
  5. Stand. When the next week closes, the same command measures it and adds a point. Recorded points are never rewritten, so the curve can only grow.

Honest scopeWhat this does and doesn't measure

  • These are qwen2.5 tokens, not Claude tokens. The Claude command-line counter reports zero usage, so it can't be used. The local model's tokenizer is exact and free. The 1 October Claude-token points are shown as anchors in their own unit, never joined to the line.
  • LIGHT's line is bytes. It shows what storage and transport would carry, not what a model would read.
  • The picture channel is not measured. It needs paid vision calls.
  • The messages are private. The measurement runs where they live, and only the numbers are published. Anyone can check the tokenizer, the code and the arithmetic; the messages themselves cannot be re-read outside the estate.
  • The figure 15× is Simon's. It appears nowhere written as a target, and nothing here claims it is reachable on new information.

For businessWhat a measured ratio does to a token bill

Teams pay for every input token their systems send a model. The useful question isn't whether 15× is possible; it's what the ratio measured on their own kind of traffic saves. This case takes the newest point's better token coding and your own volume. The model price starts at the published figure, and you can type your own. The tools themselves are MIT, with no licence fee, and run on hardware you already have.

    1. Pick one stream your systems send a model: tickets, reports, records.
    2. Write down the bars before anything is built, and seal them.
    3. Snapshot the stream privately; split it into weeks; let each coding learn only from the past.
    4. Measure each week once, losslessly, and publish only the numbers.

    White paperDoes shared knowledge compound into compression?

    1 · The question

    The estate's earlier measurements found that a shared dictionary saves only what the reader already holds. As the estate's shared knowledge grows week by week, does more of each new message become something the reader already holds, so the ratio climbs?

    2 · Method

    Claims sealed before code; a private snapshot pinned by hash; complete seven-day windows from the 1 October cut; training strictly before each window; three codings, each checked lossless; tokens counted by the local model's own tokenizer, itself checked against the model's own counts on committed public texts; recorded points never rewritten.

      One estate's agents, a few weeks, a different tokenizer from the one the 15× figure was stated in, and no picture channel. A climb on this traffic would not prove one on anyone else's.

      FAQQuestions

      Why not count Claude tokens?
      The Claude command-line tool currently reports zero usage when asked to count, and a counter that counts nothing makes every ratio look like exactly 1×. The local model's tokenizer is exact, free and checkable, so the curve uses it and says so.
      Can I re-run it?
      The tokenizer, the code, the verdicts and the arithmetic, yes: the tests and the tokenizer check run anywhere. The measurement needs the estate's private messages, so it runs only where they live. Each point names the hash of the snapshot it was measured on.
      Does any data come to the supplier?
      No. This page loads only its own files, and its security policy blocks every other connection. What you type in Count your text stays in your tab.
